# Implementation plans

Create `YYYY-MM-DD-topic.md` for a substantial change when needed. Link the plan
from its stable backlog entry; avoid creating plans for routine small fixes.

A plan should state its status (proposed, agreed, in progress, or completed),
linked backlog ID, problem, scope, intended behavior, implementation steps,
validation, and unresolved decisions. Planning does not itself authorize execution.
Keep progress in the project context/history and link supporting evidence here.
