Status: authenticated catalogue search and album metadata verified (HTTP 200).
Branch: codex/qobuz-poc.

Current setup/resume instructions: [docs/qobuz.md](../qobuz.md). The sections
below record the investigation chronologically; use that guide for current
commands, pinned source checkout and cache behavior.

Evaluate taschenb/python-qobuz using a bounded, read-only catalogue request.
No audio requests, user login, data classifications or published dataset changes.

## Run

Put an issued application ID in the ignored `.env` as `QOBUZ_APP_ID=...`, or
export it in the environment. No application secret is needed for album search.

```sh
uv run scripts/qobuz_poc.py
uv run scripts/qobuz_poc.py --query 'Mozart Clara Haskil'
```

The script uses isolated `qobuz==0.0.2`, fetches at most five candidates through
`Album.search`, and saves the raw search plus first-album metadata under ignored
`.qobuz-poc/result.json`. Requests time out after 20 seconds. HTTP failures are
reported without logging request URLs or credentials. Empty search results are
not classified as a confirmed absence.

## Alternative inspected: Sei969/qobuz-dl

Source inspected 2026-11-12; repository last pushed 2026-11-11, GPL-3.0.
`qobuz_dl/qopy.py` provides `search_albums` via `catalog/search` and full
`album/get` metadata. Its constructor requires a user auth token and calls
`cfg_setup`, which probes an audio URL even when only catalogue search is wanted.
`bundle.py` extracts web-player application credentials rather than requiring
an independently issued app ID. Downloading includes segmented audio handling.
No code from this alternative was installed or executed during inspection.

For the matching PoC, avoid the full downloader constructor: catalogue access
should remain separate from audio requests. Search helpers swallow exceptions
and return `{}`, so they cannot distinguish failed requests from no matches;
our adapter must preserve explicit errors. Account/session access would still
be needed to use its normal client. Live catalogue feasibility remains unproven.

Sources: https://github.com/Sei969/qobuz-dl/blob/master/qobuz_dl/qopy.py
and https://github.com/Sei969/qobuz-dl/blob/master/qobuz_dl/bundle.py.

## Live alternate-client trial — 2026-11-12

Loaded only Sei969/qobuz-dl's `bundle.py` from an isolated checkout. Application
ID discovery succeeded without extracting app secrets. `catalog/search` using
that ID but no account token returned HTTP 401, reproduced with the reusable
probe. This is an authentication rejection, not an empty catalogue result.
No account login, audio endpoint, secret extraction or dataset change occurred.

To retry with a user-provided token in ignored `.env`:

```sh
# QOBUZ_USER_AUTH_TOKEN must be configured locally; never commit or paste it.
uv run scripts/qobuz_catalog_poc.py --source /tmp/ali-qobuz-dl-poc
# Reproduce anonymous access:
uv run scripts/qobuz_catalog_poc.py --source /tmp/ali-qobuz-dl-poc --anonymous
```

The source path must point to a trusted checkout of Sei969/qobuz-dl. It is
loaded locally, not vendored into this repository. The probe pins no upstream
checkout automatically; inspect the chosen revision before running it. It
requests five album candidates plus first-album metadata only after successful
search. Responses are ignored under `.qobuz-poc/`; credentials are never saved
there or printed. Authenticated access was subsequently verified; see the trial below.
